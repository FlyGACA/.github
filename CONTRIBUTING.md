# Contributing to FlyGACA

Thank you for helping improve FlyGACA. These guidelines apply to every repository in the organization unless a repository has its own `CONTRIBUTING.md`.

## Before you start

- Check the open issues to see if your idea or bug is already being discussed.
- For anything larger than a small fix, open an issue first so we can agree on the approach.

## Making a change

1. Create a branch from the default branch, named after the change (e.g. `fix/login-redirect`, `feat/metar-widget`).
2. Keep each pull request focused on one change.
3. Write clear commit messages in the imperative mood: `fix: correct ATPL hour minimums`.
4. Make sure the project builds and its tests pass locally.
5. Open a pull request and fill in the template.

## Aviation and regulatory content

Accuracy matters more than anything else here:

- Cite the exact GACAR part and section for any regulatory statement (e.g. `§61.109`).
- Never invent section numbers, limits or figures. If the source does not say it, neither do we.
- Keep English and Arabic versions consistent; use the terms in the project glossary.

## Code of conduct

By taking part you agree to follow our [Code of Conduct](CODE_OF_CONDUCT.md).
